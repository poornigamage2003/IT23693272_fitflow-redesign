# ADR-001: FitFlow Technical Architecture

**Status:** Accepted

## Context
FitFlow needs cross-platform delivery, AI personalization, nutrition recognition, secure identity, structured data and responsive community features.

## Decision
Use Flutter/Dart for the client, FastAPI for the main backend and AI service boundary, PostgreSQL for core data, Redis for caching/live coordination, and AWS Cognito for identity.

## Consequences
The design keeps one primary mobile/web UI codebase and a Python-first server stack, while preserving clear service boundaries. Trade-offs include operational responsibility for several managed and self-hosted components.
